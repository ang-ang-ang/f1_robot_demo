# F1 数据质量评估说明

本文说明 `analyze_f1_data_quality.py` 的使用方式、质量指标、默认门限和风险解释。该脚本只读取 MCAP，
不会生成 LeRobot 数据，适合在数据入库、人工复核、批量转换和训练前的数据 CI 中使用。

## 1. 快速使用

### 1.1 单条评估

```bash
uv run examples/f1/analyze_f1_data_quality.py \
  --raw-dir test_data/F1_data_test/episode_000001 \
  --task "Open the cardboard box with both grippers." \
  --start-time-s 3.0 \
  --end-time-s 83.5
```

### 1.2 批量评估

```bash
uv run examples/f1/analyze_f1_data_quality.py \
  --raw-dir test_data/F1_data_test \
  --episode-config examples/f1/episodes.local.json
```

### 1.3 CI 模式

```bash
uv run examples/f1/analyze_f1_data_quality.py \
  --raw-dir test_data/F1_data_test \
  --episode-config examples/f1/episodes.local.json \
  --fail-on-high-risk
```

存在 `severity=high` 且 `status=fail` 的项目时，CI 模式以状态码 `2` 退出。

## 2. 报告文件

每次运行创建唯一目录，避免覆盖历史结果：

```text
artifacts/f1_quality_reports/<UTC时间>_<输入目录名>/
├── quality_report.json
├── quality_report.md
├── risks.csv
├── episodes/
│   ├── episode_000001.json
│   └── episode_000002.json
└── *_observation_images_*.jpg
```

文件用途：

- `quality_report.json`：完整机器可读结果，适合 CI、数据库入库和统计；
- `quality_report.md`：中文人工复核报告；
- `risks.csv`：扁平风险表，可按 Episode、状态和严重度筛选；
- `episodes/*.json`：单条 Episode 的完整指标；
- 联系表 JPG：三路相机均匀抽帧，用于快速检查视角、曝光、模糊和任务结果。

可以用 `--output-dir` 修改报告根目录。建议把报告上传到实验制品存储，但不建议直接提交大量抽帧图到 Git。

## 3. 总体状态

| 状态 | 含义 |
| --- | --- |
| `pass` | 没有失败项和告警项 |
| `warning` | 可以继续人工判断，但存在需要确认或修复的问题 |
| `fail` | 存在高严重度失败项，不应直接进入普通行为克隆训练 |

风险项还包含严重度：

| 严重度 | 示例 |
| --- | --- |
| `high` | 必需 Topic 缺失、NaN/Inf、图像无法解码、动作跳变、时间对齐超限 |
| `medium` | 消息大间隔、主从跟随偏差、成功标签缺失 |
| `low` | 提示性或优化性问题 |

`warning + high` 表示风险本身重要，但当前工具做了兼容处理或仍需人工确认，例如头相机时间戳被成功重建。

## 4. 时间戳质量

### 4.1 消息周期

对每个 Topic 的时间戳序列 `t` 计算：

```text
dt[i] = t[i + 1] - t[i]
```

报告以下指标：

- 消息数量；
- 覆盖时长；
- 有效频率 `(N-1)/(t_last-t_first)`；
- 最小周期；
- 中位周期；
- P95、P99；
- 最大间隔；
- 标准差；
- `dt <= 0` 次数。

中位周期反映典型发布频率，P95/P99 和最大间隔反映调度抖动、丢帧或线程阻塞。只看平均频率会掩盖短时
停顿，因此不能仅根据 `metadata.yaml` 的消息总数判断质量。

### 4.2 默认大间隔门限

| 数据流 | 默认门限 |
| --- | ---: |
| 相机 | 70 ms |
| 50 Hz 状态/TCP/夹爪状态 | 30 ms |
| 示教端/动作/夹爪命令 | 120 ms |

这些门限用于风险提示，不代表所有任务的统一标准。高速抓取、动态插装和力控接触应使用更严格门限。

### 4.3 非递增时间戳

```text
dt <= 0
```

表示时间戳重复或倒退。

- 数值状态和动作出现非递增时间戳：高风险失败；
- 图像出现非递增时间戳：记录为重要告警，并尝试按帧序号重建；
- 报告会保存修复次数和最大时间修正量。

图像能修复并不代表采集质量合格。帧序号重建会丢失真实曝光抖动信息，后续应修复相机驱动。

## 5. 固定频率重采样误差

在目标时间轴 `q[k]` 上，对每条数据流找到最近源消息 `t[j]`，定义：

```text
residual[k] = t[j] - q[k]
```

报告：

- 中位绝对误差；
- P95 绝对误差；
- 最大绝对误差。

默认门限：

| 数据 | 默认最大误差 |
| --- | ---: |
| 三路图像 | 40 ms |
| 机器人状态 | 15 ms |
| 动作命令 | 60 ms |

风险解释：

- 图像误差过大：视觉和机器人姿态不对应；
- 状态误差过大：模型看到的 proprioception 已经过时；
- 动作误差过大：训练标签可能对应另一个控制周期；
- 三路相机误差方向长期不同：可能存在固定相机延迟或时钟偏移。

不要通过无限放宽门限来通过数据。可以先降低输出 FPS，但根本解决方法是统一时钟和减少采集链路阻塞。

## 6. 数值有效性

对每个数值 Topic 报告：

- 数组形状；
- JointState 名称；
- NaN 数量；
- Inf 数量；
- 有限值比例；
- 每维 min/max/mean/std；
- 标准差接近零的常量维度。

任何用于状态或动作的 NaN/Inf 都是高风险失败项。

常量维度不一定错误。例如当前 `/hal/joint_states` 包含头部、身体和手部维度，但数据中部分维度始终为零；
转换器只按名称选择左右臂 14 个有效关节。若本应运动的维度成为常量，则可能是驱动未发布、名称错位或传感器冻结。

## 7. 动作连续性

对重采样后的 14 个关节动作计算：

```text
step[k, joint] = abs(action[k + 1, joint] - action[k, joint])
```

默认在任一关节单步超过 `25°` 时告警，并保存最大的 10 个跳变位置。

常见原因：

- 示教端接管从机；
- 示教离合松开后重新定位；
- 控制模式切换；
- 急停恢复；
- 消息损坏或关节顺序变化；
- 操作者真实地给出了很激进的目标。

动作跳变不能只靠平滑掩盖。首先应查看对应图像、从机响应和控制日志，判断它是否属于任务行为。

## 8. 主从跟随误差

在统一时间轴上计算：

```text
tracking_error = abs(leader_joint_target - follower_joint_state)
```

报告每个关节的：

- 中位绝对误差；
- P95；
- 最大值；
- 全局 P95；
- 最差关节 P95。

默认最差关节 P95 门限为 `10°`。

误差偏大可能来自：

- 真实控制延迟；
- 关节速度/加速度限幅；
- 碰撞或机械阻力；
- 主从标定偏差；
- 时间戳错位；
- 动作目标跳变；
- leader Topic 并不是真正下发给机器人的动作。

该指标用于验证 `/lead/joint_states` 是否适合作为训练动作，也帮助决定是否需要显式动作延迟补偿。

## 9. 图像抽样质量

默认每个相机均匀抽取 24 帧，报告：

- 解码成功数；
- 分辨率及是否变化；
- JPEG format；
- frame id；
- 压缩数据大小；
- 平均亮度；
- 极暗像素比例；
- 极亮像素比例；
- 拉普拉斯方差；
- 抽样压缩帧哈希重复数；
- 联系表图片。

拉普拉斯方差只能作为模糊线索，不能跨相机直接比较固定阈值：纸箱表面纹理少、近距离遮挡或景深变化都会降低该值。
最终仍需要人工查看联系表或视频。

调整抽帧数量：

```bash
--image-samples 48
```

禁用联系表：

```bash
--no-save-contact-sheets
```

完整转换会解码每一帧；独立评估默认只抽样解码，避免每次质检都产生完整视频解码开销。

## 10. TCP 单位和姿态环绕

脚本比较：

- `/state/left_arm/tcp_pos`；
- `/lead/left_tcp`。

如果二者平移量级相差超过 100 倍，提示米/毫米单位风险；如果示教 TCP 欧拉角单步超过 `180°`，提示
`-180°/+180°` 环绕。

该风险不会影响当前默认的关节空间训练，因为 TCP 没有写入 `observation.state` 或 `action`。如果以后训练
TCP-space policy，必须先完成：

1. 坐标系定义统一；
2. 米/毫米统一；
3. 度/弧度统一；
4. 左右手坐标约定统一；
5. 欧拉角转换成连续的旋转 6D、旋转矩阵或正确处理符号的四元数；
6. 部署端实现完全相反的输出变换。

## 11. 任务和成功标注

MCAP 和当前 `metadata.yaml` 没有 Pi0.5 所需的任务语言文本和成功结果，因此脚本会检查 Episode 配置：

- 没有 `task`：高风险失败；
- 没有 `success`：中风险告警；
- `success=true`：通过，但仍建议抽样复核；
- `success=false`：高风险失败，普通行为克隆中应 `include=false`。

成功标准必须针对任务预先定义。例如开箱任务可以要求：

- 指定箱盖全部打开；
- 箱体未倒下；
- 夹爪未卡住；
- 操作完成后双臂安全退出；
- 目标区域可见。

如果不同标注人员对成功的理解不同，模型会同时学习互相冲突的终止状态。

## 13. 建议的数据验收流程

每次采集完成后：

1. 自动运行未裁剪质量评估；
2. 人工查看三路相机联系表；
3. 标记任务、成功、失败原因和裁剪边界；
4. 使用裁剪配置再次运行质量评估；
5. 高风险失败项不得进入普通训练集；
6. 转换器 dry-run；
7. 正式转换并保存转换报告；
8. 从 LeRobot 随机读取若干帧，核对图像颜色、状态顺序、动作顺序和任务文本；
9. 按 Episode/采集 Session 划分训练、验证、测试；
10. 计算 normalization stats；
11. 启动小规模训练并做离线数据回放；
12. 最后才进入限速、带急停的真机测试。
